# Screen-to-backend connections

Reviewed 4 November 2026 against the agreed 94-screen index and the current Java controllers. These are connection instructions, not a claim that role screens have been implemented in React Native.

**MAPPED** means the core workflow has matching API operations. **PARTIAL** means at least one planned control still needs backend work. **POLICY_DEFERRED** is the agreed access-help boundary. Do not enable a button that promises an operation listed as remaining.

Every school path below starts with `/api/v1/schools/{school}`. Account routes start with `/api/v1`. Use exact request fields from [FRONTEND_ENDPOINTS.md](FRONTEND_ENDPOINTS.md), and permitted roles/versions from [API.md](API.md). The same page has different actions for Principal, School Office and Accounts.

All applicable attachment pages also use: `POST /files` → `PUT /files/{fileId}/content`; preview/download with `GET /files/{fileId}` and `GET /files/{fileId}/content`. This does not make unsupported admission/history/material file purposes available.

Navigation, dropdown opening, form typing, local draft state, loading/error rendering and native share/print are frontend work. The Model adapts API fields; the Presenter coordinates calls; Views render state and send actions. Official grades, money and promotions come from Java.
